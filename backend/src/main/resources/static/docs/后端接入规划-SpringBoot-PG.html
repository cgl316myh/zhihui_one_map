一、目标与范围

目标

  • 用 Spring Boot + MyBatis + PostgreSQL 替换浏览器内「伪后端」（用户、阈值、储量、地图、字典、审计等 localStorage）。
  • 大屏读接口尽量保持现有 JSON DTO，降低前端改动面。
  • 鉴权统一为 JWT Bearer；角色仍为 admin / user。

一期范围（做）

  • 认证注册、用户管理、字典、操作审计
  • 后台配置：环境阈值、储量参数、地图源与密钥、传感器网关配置镜像
  • 业务主数据：生产、视频、点位元数据；大屏读接口聚合
  • 告警列表由服务端按环境/边坡/生产/视频状态汇聚

一期不做（明确排除）

  • 全量时序仓库化与历史曲线长期归档（表结构预留，写入放二期）
  • 立即淘汰 Python sensor_bridge（一期继续负责 MQTT/HTTP 采集）
  • 改写边坡第三方厂商原始协议（仍通过 bridge 或兼容 DTO）

技术约定

项约定
工程位置src/backend/，模块名 mine-one-map-api
接入策略分阶段：Spring 先接管认证与配置与业务主数据；实时采集暂留 sensor_bridge
鉴权JWT Bearer（登录发 Token；管理接口与需登录读接口校验）
演示模式保留前端 STATIC_DEMO；接真后端时关闭，Vite /api 代理指向 Spring（如 8080）
用户密码哈希BCrypt；迁移时废弃前端 SHA-256 本地哈希
Git 主干禁止在 master 上直接开发；日常在 develop / feature 分支进行

用户名postgres开发环境直接用超级用户，不单独建业务账号
密码postgres（默认）按本机 postgres 口令修改；可用环境变量 DB_PASSWORD 覆盖

1.2 GitHub 分支策略（后端接入起强制执行）

  • 不再在 master 上直接开发或提交功能代码。master 仅接收经评审合并的稳定版本（演示站 / Pages 仍可从 master 发布）。
  • 长期开发集成分支：develop（后端接入工作的默认基线）。
  • 所有功能、修复从 develop 拉出短生命周期分支，完成后 PR 合回 develop；阶段稳定后再合入 master。

分支命名方式

类型命名格式示例
长期开发线 develop develop
功能（按里程碑） feature/m<N>-<短横线描述> feature/m1-backend-skeleton

功能（按模块） feature/<模块>-<短横线描述> feature/backend-flyway-init

规则：全小写；单词用短横线 -；禁止空格与中文；描述尽量短（建议 ≤ 5 段）。

四、PostgreSQL 表设计（一期）

4.1 系统与权限

表用途关键字段（示意）
sys_user 用户账号 id, username, password_hash, display_name, role(admin/user), enabled, last_login_at, created_at, updated_at
sys_audit_log 操作审计 id, actor, action, target, result, summary, ip, created_at
sys_dict_type 字典类型 code, name, remark
sys_dict_item 字典项 type_code, item_code, label, sort_no, enabled

4.2 配置类（后台可改）

表用途说明
cfg_env_threshold 环境昼/夜阈值 可用 JSONB 存完整阈值树，或按 metric+period 行式；建议一期 JSONB 对齐现有文件结构
cfg_map 默认底图、最小缩放、天地图 tk、basemaps JSONB；敏感 tk 仅 admin 写，公开接口可脱敏或下发只读
cfg_sensor_bridge MQTT/HTTP/站点映射 JSONB 对齐 sensor_bridge/config.json；保存后可选推送到 bridge
cfg_reserves 储量输入参数 评估利用、回采率、已采出、日均、采区数组(JSONB)、趋势/预测可选

4.3 业务主数据

表用途说明
biz_production 生产工段与设备快照 一期可用单行 JSONB 对齐 production.json；后续拆 line/device
biz_video_camera 视频点位 id, name, lng, lat, online, scene, sort_no
biz_map_point 边坡/雨量/环境点位元数据 对齐 slope-points.json 与环境坐标；type + 外部设备 id

4.4 二期预留（建表可空跑，一期可不写）

  • ts_env_sample：环境时序（point_id, metric, value, sampled_at）
  • ts_slope_sample：边坡位移时序（point_id, x, y, h, magnitude, sampled_at）

一期历史曲线仍可沿用点位内嵌短历史或 bridge 内存；入库与查询放 M4 之后。

五、API 分组清单

统一前缀 /api。除特别说明外，管理接口需 ROLE_ADMIN；大屏读接口需登录（admin 或 user）。响应建议：{ code, message, data }。

5.1 认证 /api/auth

方法路径权限说明
POST /api/auth/login 匿名 用户名+密码(+验证码可选) → accessToken / expiresIn / user
POST /api/auth/register 匿名或开关控制 注册默认 role=user
POST /api/auth/refresh 持 refresh 或未过期 token 刷新 accessToken（可选）
GET /api/auth/me 登录 当前用户资料
POST /api/auth/logout 登录 可选黑名单；前端删 Token 即可

5.2 管理后台 /api/admin

方法路径说明
GET POST PUT DEL /api/admin/users 用户 CRUD、启用禁用、重置密码
GET PUT /api/admin/thresholds 环境昼/夜阈值
GET PUT /api/admin/reserves 储量参数；服务端可派生可采/回采率
GET PUT /api/admin/map 地图源与密钥
GET PUT /api/admin/sensors sensor_bridge 配置镜像；可选触发同步
GET POST PUT DEL /api/admin/dict 字典类型与字典项
GET /api/admin/audit 审计查询（分页、按 action/actor 过滤）

5.3 大屏读接口（DTO 兼容现网关 / mock）

方法路径说明
GET /api/environment 环境点列表 + metrics；与现 JSON / bridge 对齐
GET /api/slope 边坡位移 + 雨量；保留 points / rainfall / updatedAt / live
GET /api/production 生产工段
GET /api/video 摄像头列表（或 /api/video/cameras）
GET /api/reserves 储量只读派生结果
GET /api/alerts 服务端汇聚最近报警
GET /api/sensors/latest 过渡兼容：聚合 env+slope（或反向代理 bridge）
GET /api/config/public 非密钥地图默认项、轮询间隔等

轮询间隔建议与现网一致：边坡约 30s；环境可复用同一 bundle 或独立接口。

六、分阶段里程碑

  1. M1 · 工程骨架
    创建 src/backend；接 PG；Flyway 初版表；Spring Security + JWT；种子用户 admin/user；POST /api/auth/login 联调通过。
  2. M2 · 后台配置落库
    阈值 / 储量 / 地图 / 传感器配置 / 字典 / 审计 CRUD；改造 admin.html 调 API，去掉对应 localStorage 权威源。
  3. M3 · 大屏读接口
    production / video / reserves / alerts 由 Spring 提供；env/slope 经 Spring 代理或拉取 bridge；关闭 STATIC_DEMO 做联调；Vite 代理改 8080。
  4. M4 · 采集收敛
    bridge 最新态写入 PG（或 MQTT 迁入 Spring）；启用 ts_* 时序表；历史曲线改查库。

七、前端改造要点

文件改造要点
js/demoMode.js 接真后端时 STATIC_DEMO = false；区分「静态演示」与「API 模式」
js/auth/users.js / session.js 登录改调 /api/auth/login；Token 存 sessionStorage/memory；请求头 Authorization: Bearer …
js/admin.js 各面板 save/load 改 REST；失败提示；审计由服务端写
js/app.js / js/api/* loadMockBundle 改为 API bundle 或分接口；slope 轮询 baseUrl 指向 Spring
vite.config.js /api proxy target：开发指向 http://127.0.0.1:8080（Spring）；bridge 可挂子路径或由 Spring 转发

可继续保留静态 JSON 作为离线演示与 GitHub Pages 回退；正式环境以 PG 为准。

八、风险与兼容

  • GitHub Pages：无服务端，继续 STATIC_DEMO + public/data/*.json；本规划不影响静态演示站。
  • 天地图密钥等：勿再仅存前端可写 localStorage；改服务端下发，admin 写库。
  • DTO 漂移：env/slope 以现有 sensor_bridge 与 docs/边坡系统接口说明.html 为准，Spring 做适配层，避免大屏大改。
  • 双写窗口：M2–M3 期间禁止「前端 localStorage 与 PG」双权威；以服务端为准，必要时提供「导入 JSON 一次」迁移工具。
  • CORS：前后端分端口时显式配置允许源与 Authorization 头。
  • 密码迁移：旧本地 SHA-256 哈希不可直接复用；上线前重置演示账号或强制改密。
  • 库口令：开发默认 postgres/postgres；本机密码不同时用 DB_PASSWORD 覆盖，勿把生产口令提交进仓库。
  • 分支误用：误在 master 提交时，应迁到 feature/* 再 PR，避免直接 force 改写已发布历史。

一键只启 backend（已落地）

  • Vite 构建产物在 Maven 阶段拷贝到 classpath:/static/，与 API 同端口。
  • 启动：cd src/backend && .\run.ps1 或 mvn spring-boot:run。
  • 访问：http://127.0.0.1:8080/（登录）、/index.html、/admin.html。
  • 跳过前端构建：-Dskip.frontend=true。
