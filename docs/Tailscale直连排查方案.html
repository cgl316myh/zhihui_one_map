Tailscale 直连排查方案

目标：让本机（singlemypc）与云南 Server99（yunnan-server99）建立 direct 直连，避免流量绕行旧金山 DERP 中继导致上传极慢。

文档路径：docs/Tailscale直连排查方案.html 当前问题：经 DERP(sfo) 中继 目标状态：via … direct

1. 背景结论（已实测）

本机 Wi‑Fi → Tailscale DERP(sfo 旧金山) → Server99

实测上传约 0.05 Mbps（4MB 约 11 分钟），延迟常在 0.5–2 秒。阿里云北京 ECS 不在这条链路上，与本次上传慢无关。

本机 → UDP 直连（P2P） → Server99

直连成功后，大文件传输通常可提升一个数量级以上；仍受双方实际上行带宽限制。

2. 复杂度说明

情况难度说明
一方有公网 + UDP 可打通 低 多数只需检查防火墙/端口，几分钟验证
本机运营商 NAT / 公司网 / 对称 NAT 中～高 可能直连失败，需改网络或退回国内自建 DERP / 公网直传
软件侧配置 低 一般不必改复杂配置文件；关键看 tailscale ping 结果

对你们：Server99 有公网与 UPnP，条件较好；本机侧（Wi‑Fi / NAT）更可能是瓶颈。

3. 成功标准

tailscale ping yunnan-server99

在本机 PowerShell 执行。成功示例关键词：

pong from yunnan-server99 (...) via <ip:port> in XXms
# 或提示中出现 direct
# 失败特征：via DERP(sfo) / via DERP(...) 且提示 direct connection not established

4. 分步操作清单

步骤 A · 本机（singlemypc）

# 本机执行
tailscale status
tailscale netcheck
tailscale ping -c 8 yunnan-server99

关注：是否仍写着 active; relay "sfo"；ping 是否变成 direct。

步骤 B · Server99（yunnan-server99）

# Server99 执行
tailscale status
tailscale netcheck
tailscale ping -c 8 singlemypc

# 查看本机防火墙中与 Tailscale / 41641 相关的规则（可选）
Get-NetFirewallRule -DisplayName *Tailscale* | Select-Object DisplayName, Enabled, Direction, Action
Get-NetUDPEndpoint -LocalPort 41641 -ErrorAction SilentlyContinue

步骤 C · 对照判断

现象含义下一步
ping 显示 direct 直连成功 再传一个 50–100MB 文件验证速度即可
仍 DERP(sfo) / 未 direct UDP 打洞失败 本机换有线/手机热点对比；检查双方防火墙；见第 5 节备选
ping 超时或大量丢包 链路不稳或策略拦截 先保证 tailscale status 双方 online，再查 UDP

5. 直连搞不定时的备选（由易到难）

  1. 大文件不走 Tailscale：用 Server99 公网 IP 做 SSH/SMB 端口映射，或同局域网用 192.168.2.199。
  2. 国内中转：本机 → 北京阿里云 / OSS → 再拉到云南（两段都是国内）。
  3. 自建国内 DERP：在北京 ECS 跑 derper，客户端自定义 DERP map（比直连配置略多，但可控）。
  4. 自建 WireGuard：适合要长期稳定组网、且能接受改客户端方案时。

6. 关键节点速查

本机

Tailscale：100.95.58.63（singlemypc）
局域网：WLAN 192.168.1.110
最近官方 DERP：东京（约 65ms）

Server99

Tailscale：100.122.107.85（yunnan-server99）
局域网：192.168.2.199（1 Gbps）
公网约：112.117.63.50

7. 建议执行顺序（最短路径）

  1. 本机、Server99 各执行一次 tailscale ping，截图/复制结果。
  2. 若非 direct：本机改有线或临时用手机热点再 ping 一次（判断是否本机 NAT 问题）。
  3. 仍失败：检查 Server99 入站 UDP / 前端路由；仍失败则改用公网直传或北京中转，不必死磕。
  4. 直连成功后再传 JAR/瓦片等大文件。

一句话

直连配置本身不复杂，成败取决于 UDP 能否打通；用 tailscale ping 是否出现 direct 作为唯一验收标准即可。
