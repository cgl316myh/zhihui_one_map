矿区储量数据获取与计算说明

安宁隆瑞混凝土有限责任公司采石场 · 智慧矿山一张图「矿区储量分析」面板
对应大屏区块：服务年限 / 可采储量 / 剩余可采 / 全矿回采率 / 采区回采率表

单位：万吨 基准时点：2025-12-31 计算模块：js/modules/reserves.js 录入在管理后台；大屏只读派生结果

一、数据如何获取（从年报到大屏）

储量不是传感器实时采集，而是由矿山储量年度报告整理后，经后台配置入库，前端按固定公式派生展示。

1
官方年报
《安宁隆瑞混凝土有限责任公司采石场 2025 年矿山储量年度报告》，统计截止日 2025-12-31。报告原始单位为千吨。
2
种子 / 默认配置
换算为万吨（÷10）后写入 src/backend/src/main/resources/seed/cfg_reserves.json；库表 cfg_reserves 为空或缺 2025 数据时由 DataInitializer 导入/覆盖。
3
数据库与接口
运行时真源为 PostgreSQL 表 cfg_reserves.payload（JSON）。大屏：GET /api/reserves；管理端：GET/PUT /api/admin/reserves。
4
前端派生计算
reserves.js 的 computeReservesDerived() 根据录入字段重算可采储量、剩余、服务天数、采区/全矿回采率；panels.js 的 renderReserves() 渲染截图中的 KPI 与表格。
5
人工维护
管理后台 →「储量参数」可改评估利用、回采率、已采出、日均采出、采区行等；保存后写入库表，大屏刷新可见。API 模式下不以浏览器 localStorage 为准。

二、大屏各指标如何计算

1. 可采储量

可采储量 = 评估利用资源储量 × 设计回采率 × 采矿回采率
9677.26 × 1.0 × 0.95 = 9193.397 → 展示 9193.4 万吨
  • 评估利用资源储量（assessedUtilizedReserve）：对齐年报「保有资源量 / 控制资源量」。年报 96772.59 千吨 → 系统 9677.26 万吨。
  • 设计回采率（designRecoveryRate）：对齐年报「可信系数」，当前 1.0（100%）。
  • 采矿回采率（miningRecoveryRate）：对齐年报回采率，当前 0.95（95%）。
  • 年报「可信储量」口径：保有 × 可信系数 × 回采率；与上式一致（91926.51 千吨 ≈ 9192.65 万吨，与系统四舍五入到 2 位后的 9193.4 同量级）。

2. 剩余可采

剩余可采 = 可采储量 − 累计已采出
9193.4 − 0 = 9193.4 万吨
  • 当前台账以截止 2025-12-31 的保有/可信储量为起点，mined = 0，故剩余可采 = 可采储量。
  • 投产后续计采出后，在后台更新「累计已采出」即可压低剩余可采。

3. 服务年限与预计天数

预计剩余天数 = round(剩余可采 ÷ 日均采出)　（日均 > 0）
服务年限（年）= 预计剩余天数 ÷ 365　（保留 1 位小数）
日均采出 avgDailyMined = 0.389 万吨/天
  （按 2025 年开采量 141.98 万吨 ÷ 365 ≈ 0.389）

剩余天数 = round(9193.4 / 0.389) = 23633 天
服务年限 ≈ 23633 / 365 ≈ 64.7 年
  • 预警阈值 warningYears 默认 3 年；服务年限 ≤ 预警时大屏改警示文案。
  • 截图中「服务年限约 64.7 年（预警阈值 3 年）」即由此得到。

4. 采区回采率（表）

采区回采率 = 采出量 ÷ 动用储量

「采区」行默认是年度采剥汇总（年报年度开采/动用），不是 GIS 空间采区边界。

采区名称 采出 output 动用 activatedReserve 回采率 年报原值（千吨）
2025年度采剥区 141.98 148.67 141.98 / 148.67 ≈ 95.5% 1419.83 / 1486.73
2024年度采剥区 94.42 99.39 94.42 / 99.39 ≈ 95.0% 944.16 / 993.85
2023年度采剥区 189.68 199.66 189.68 / 199.66 ≈ 95.0% 1896.76 / 1996.59

5. 全矿回采率（按采出量加权）

全矿回采率 = Σ(采区回采率 × 采区采出量) ÷ Σ(采区采出量)
分子 = 0.955×141.98 + 0.95×94.42 + 0.95×189.68
分母 = 141.98 + 94.42 + 189.68 = 426.08
全矿回采率 ≈ 95.2%（大屏展示 mineRecoveryRatePct）

注意：全矿回采率来自采区表加权，不是直接用采矿回采率 95.0%；因 2025 行 95.5% 权重拉高后约为 95.2%。

三、年报字段对照（千吨 → 万吨）

系统字段 年报含义 年报原值（千吨） 系统取值（万吨）
assessedUtilizedReserve 保有资源量 96772.59 9677.26
designRecoveryRate 可信系数 — 1.00
miningRecoveryRate 回采率 95% — 0.95
recoverableReserve（派生） 可信储量 91926.51 ≈9193.4（系统推算）
mined 台账累计已采出（相对当前保有基准） — 0
avgDailyMined 2025 开采量 ÷ 365 1419.83 / 年 0.389
warningYears 服务年限预警阈值 — 3

完整快照见配置 JSON 中的 reportSnapshot、dataBasis； 种子文件：seed/cfg_reserves.json。

五、维护注意

  1. 取得新年度矿山储量报告后：更新保有资源量、采区采出/动用、日均采出，并同步 reportSnapshot。
  2. 「累计已采出」相对当前保有基准日记账；换新年报基准后通常重置为 0，再按生产台账累加。
  3. 趋势曲线 / 日采出日历多为示意插值，便于大屏展示，不能当作独立勘探成果。
  4. 管理端 PUT 会保护库中已有 2025 采区与年报快照，避免旧客户端误覆盖（见 protectYear2025）。
